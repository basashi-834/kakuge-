# KAKUGE (C++版)

Windows 10/11 でダブルクリックだけで起動する、追加インストール不要のデスクトップ2D対戦格闘ゲームです。
以前の PowerShell + WinForms 版を全面的に **C++ + Win32 API + GDI+** で書き直したバージョンです。

## まず起動したい方へ

`Kakuge.exe` を **Data フォルダ・Audio フォルダと同じ場所に置いたまま**、`Kakuge.exe` をダブルクリックしてください。
インストーラーはありません。コンパイラも .NET も要りません。Windows 10/11 標準の機能だけで動きます。

```
このフォルダ(どこでもOK)
├─ Kakuge.exe   ← これをダブルクリック
├─ Data\        ← キャラクター・技データ(同じ場所に置いておく)
└─ Audio\       ← 効果音を入れる場所(空でもOK、無音のまま動きます)
```

## なぜ C++ に切り替えたか

前回の PowerShell + WinForms 版は「追加インストール不要」という制約は満たしていましたが、実機で
文字コード起因のエラー・イベントハンドラのクロージャ問題・例外処理の呼び出し順序エラーなど、
スクリプト言語ならではの実行時トラブルが繰り返し発生しました。

C++ + Win32 + GDI+ に切り替えることで、
- **静的リンクした単一の `.exe`** として配布でき、PowerShell の文字コード/実行ポリシー問題が原理的に発生しない
- コンパイル時に多くのミスを検出できる(実際、この後の「テストについて」で述べる通り、実行前にいくつかのバグを検出・修正できました)
- 依存する DLL は `gdiplus.dll` / `kernel32.dll` / `user32.dll` / `shell32.dll` / `msvcrt.dll` / `winmm.dll` のみで、
  すべて **Windows 10/11 に最初から入っているシステムDLL** です。追加のランタイム(Visual C++ 再頒布可能パッケージ等)は一切不要です。

という利点があります。実行ファイルは Linux 上の開発環境で **mingw-w64 (`x86_64-w64-mingw32-g++`)** を使ってクロスコンパイルしており、
あなたの PC 側では一切コンパイル作業をする必要はありません。

## 動作確認について(重要)

このセッションは Linux サンドボックス上で開発しているため実機の Windows がありません。そこで今回は
**Wine + Xvfb(仮想ディスプレイ)を使い、実際に `.exe` を起動してスクリーンショットを撮りながら検証しました。**
前回の PowerShell/WinForms 版では UI 層は一度も実行できず「構文チェックのみ」でしたが、今回はタイトル画面から
キャラクターセレクト→VS画面→対戦→ポーズメニュー→リザルト→設定画面→キャラクターエディター(新規キャラ作成含む)まで、
実際にクリック・キー入力をシミュレートして一通り動作させ、その過程で **実際に3件のバグを検出して修正しました**:

1. Wine 環境にフォントが一切無く `Segoe UI` が解決できず文字が全く描画されない問題
   → `Segoe UI` が見つからない場合は GDI+ の汎用サンセリフ体にフォールバックするよう修正(実機なら通常 `Segoe UI` が使われます)
2. キャラクターエディターで「+ NEW CHARACTER」を押すと、裏にある編集フォームのラベルが隠れずに重なって表示される問題を修正
3. 新規キャラクター作成後、キャラクター選択コンボボックスが新しいキャラクターを選択しない問題を修正

ただし、Wine は完全な Windows 互換環境ではありません(このテスト環境には日本語フォントも一切無いため、
キャラクターエディターの技名ドロップダウンで日本語が「□□□」のように表示される場面がありましたが、これは
Wine 側にフォントが無いことが原因と判断しています。実機の Windows には日本語フォントが標準で入っているため
再現しない可能性が高いですが、**実機でも念のため技名の表示だけは確認してください**)。
何か表示が崩れている・操作できない箇所があれば教えてください。

## プロジェクト構成

```
cpp-game/
├─ Kakuge.exe          配布用の実行ファイル(ビルド済み)
├─ Data/                 キャラクター・技データ(JSON)
│   ├─ characters/ryu.json
│   ├─ moves/ryu/*.json (11技)
│   └─ match_rules.json  (ラウンド時間などのルール設定)
├─ Audio/                効果音を置く場所(空でもOK、無音のまま動作)
├─ README.md             このファイル
└─ src/                  C++ ソースコード一式(実行には不要、改造・再ビルド用)
    ├─ engine/            ゲームロジック本体(Windows API に一切依存しない)
    │   ├─ Constants.h / Boxes.h / CharacterStats.h / MoveData.h
    │   ├─ MoveExecutor.h / StateMachine.h / SuperGauge.h / InputSystem.h
    │   ├─ Fighter.h / Projectile.h / CPUAI.h / BattleSystem.h
    │   ├─ DataManager.h (JSON 読み書き) / Settings.h (解像度設定)
    ├─ platform/          Win32 / GDI+ 描画・ウィンドウ・入力
    │   ├─ WinMain.cpp    エントリポイント、ウィンドウ・メッセージループ・音声再生
    │   ├─ App.h/.cpp     画面遷移・ゲームループ・入力集約
    │   ├─ Screens.cpp    Title/CharacterSelect/VS/Game/Result/Settings 画面
    │   ├─ Editor.cpp     キャラクターエディター(ネイティブコントロール使用)
    │   ├─ Draw.h/.cpp    GDI+ 描画ヘルパー(人型キャラ・HUD・バー等)
    │   └─ Layout.h / Palette.h  座標変換・配色
    ├─ tests/EngineTests.cpp  ゲームロジックのユニットテスト(30項目)
    ├─ third_party/nlohmann/  JSON ライブラリ(ヘッダオンリー、同梱)
    ├─ build_windows.sh   Windows向け .exe クロスビルドスクリプト
    └─ build_linux_tests.sh  ロジックテストのネイティブビルド・実行スクリプト
```

**engine/ と platform/ を分離している理由**: engine/ 配下は Windows 系ヘッダを一切 `#include` していない、
プラットフォーム非依存の C++17 コードです。そのため Linux 上でも普通の `g++` でそのままコンパイル・実行でき、
`tests/EngineTests.cpp` によるロジックの自動テストが(Wine やクロスコンパイルなしで)可能になっています。
Win32 API・GDI+ に依存する部分は platform/ にすべて隔離されています。

## テストについて

`src/tests/EngineTests.cpp` は状態機械・判定・ガード・コマンド入力・キャンセル猶予・データ保存/読込・
新規キャラクター作成など **30項目** を検証する自動テストです(旧 PowerShell 版のテストを1:1で C++ に移植し、
新機能のテストを追加したもの)。開発中、Linux 上で毎回このテストを実行し、**30/30 成功**を確認しています。

```
cd src
./build_linux_tests.sh
```

## 画面構成

- **タイトル画面**: GAME START / CHARACTER EDIT / SETTINGS / EXIT
- **キャラクターセレクト画面**(新規): プレイヤー→CPU の順にキャラクターを選択。ポートレート・
  POWER/STAMINA/SPEED/REACH のステータスバー付き。「+ ADD CHARACTER」タイルからその場で新規キャラを作成可能。
- **VS画面**(新規): 対戦カード演出。任意のキーで対戦開始までスキップできます。
- **対戦画面**: HP/超必殺ゲージ/ラウンドタイマー/コンボカウンター表示。
- **ポーズメニュー**(Escで開閉): RESUME / GIVE UP → TITLE に加えて、**CPU側(P2)の挙動を CPU / 立ち / しゃがみ / ジャンプ
  の4種類に切り替えられます**(練習用)。
- **リザルト画面**: 勝敗・MAX COMBO・TIME LEFT・DAMAGE TAKEN。REMATCH / CHARACTER SELECT / TITLE。
- **設定画面**(新規): 解像度を 320x200 〜 1920x1080 の9段階(4:3・16:9・16:10)から選択できます。
  画面・HUD・キャラクター(人型ライン画)はすべて仮想キャンバス(1280x720)上に描画し、選んだ解像度に
  一括で拡大縮小(レターボックス)しているため、**どの解像度を選んでもキャラクターや文字が正しい比率で表示されます**。
- **キャラクターエディター**: 既存キャラの基礎ステータス・技のフレームデータ(発生/持続/硬直/ダメージ/
  ヒット硬直/ガード硬直/ヒットストップ)を編集・保存。技選択ドロップダウンは技IDではなく **技の表示名**
  (「昇龍拳」等)で表示するよう修正済みです。「+ NEW CHARACTER」から新規キャラクターをその場で作成でき、
  既存キャラの技構成をテンプレートとして複製して土台にします。

## 今回のPowerShell版からの主な変更点

1. 実装言語を PowerShell から **C++17** に全面移植(ロジックは1:1で移植、挙動は変えていません)
2. 配色を暗いチャコール基調から、参考画像に合わせた **白/赤/黒の明るいテーマ** に変更
3. **キャラクターセレクト画面**・**VS画面** を新規追加
4. ポーズメニューに **CPU/立ち/しゃがみ/ジャンプ の切替**(練習用ダミーモード)を追加
5. キャラクターエディターの技ドロップダウンを **技名表示** に修正(以前はファイル名がそのまま出ていました)
6. キャラクターエディターから **新規キャラクターをその場で作成** できる機能を追加(既存キャラの技構成を複製)
7. **設定画面**を新規追加し、解像度を 320x200 ~ 1920x1080(4:3/16:9)の範囲で変更可能に。
   キャラクター・HUD含め全画面が解像度に応じて自動スケーリングされます
8. HUD に **コンボカウンター**(N HIT COMBO)を追加、リザルト画面に MAX COMBO を表示

## 今回のスコープ外・簡略化した点

- **キャラクターエディターで編集できる項目**: 基礎ステータス全般と、技の
  表示名/発生/持続/硬直/ダメージ/ヒット硬直/ガード硬直/ヒットストップ に対応しています。
  判定枠のサイズ・オフセット、キャンセルルート、タグ、無敵時間、飛び道具パラメータ等の高度な項目は
  今回のフォームでは編集できません。必要な場合は `Data\moves\<キャラID>\<技ID>.json`(または編集後は
  `%APPDATA%\Kakuge\moves\<キャラID>\`)を直接テキストエディタで編集してください。スキーマは
  旧PowerShell版と同一です。
- **キャラクター固有のイラスト**は用意していません(全キャラクター共通のライン画人型モデルで、
  頭身・カラーのみキャラごとに変わります)。新規作成したキャラクターも同じ人型モデルを使います。
- **効果音**はファイルを同梱していません。`Audio\attack.wav` / `hit.wav` / `block.wav` / `ko.wav`
  (非圧縮PCM .wav)を置くと自動的に再生されます(旧PowerShell版と同じ仕組みです)。
- キャラクターセレクト画面の「?」プレースホルダー演出(参考画像にあった、未解禁キャラのような表示)は
  実装していません。表示されるのは実際に存在するキャラクターと「+ ADD CHARACTER」のみです。

## 保存データの場所

キャラクター・技の編集内容、新規作成したキャラクター、画面解像度の設定は、いずれも
`%APPDATA%\Kakuge\` 以下に保存されます(`Kakuge.exe` と同じフォルダの `Data\` は書き換えません)。
アンインストールしたい場合は `Kakuge.exe` とその周辺フォルダを削除し、
`%APPDATA%\Kakuge\` フォルダも削除してください。

## ソースコードから再ビルドしたい場合(任意)

あなたの PC でビルドする必要は基本的にありません(`Kakuge.exe` はそのまま動きます)。
もし将来ソースを変更して再ビルドしたい場合は、Linux + mingw-w64 環境で以下を実行してください
(Windows 側には何もインストール不要です。ビルドは開発環境側で行い、生成された `.exe` だけを配布します)。

```bash
cd src
./build_windows.sh   # build/Kakuge.exe が生成されます
```
