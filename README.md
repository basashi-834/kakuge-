# Kakuge — 2D 対戦格闘ゲーム（C++17 + SDL2）

1990 年代のアーケード格闘ゲームを手本にした、2D 対戦格闘ゲームです。
384x224 という当時のアーケード基板と同じ内部解像度で描画し、
それを整数倍に拡大してウィンドウいっぱいに表示します。
ウィンドウの縦横比が違っても、キャンバスの側を広げて合わせるので、
まわりに黒い余白（レターボックス）は出ません。

**ビルドの手順は [BUILD_WINDOWS.md](BUILD_WINDOWS.md) を見てください。**
はじめての方向けに、1 コマンドずつ丁寧に書いてあります。

---

## 決めごと

| 項目 | 内容 |
|---|---|
| 言語 | C++17 |
| ライブラリ | **SDL2 のみ**（2.0.18 以降。`SDL_RenderGeometry` を使用） |
| ビルド環境 | Windows + Visual Studio（MSVC / CMake）。SDL2 は直接DL または vcpkg |
| コメント | 初心者向けに日本語で厚めに |

SDL2 以外のライブラリは一切使いません。そのため、
本来なら外部ライブラリに頼る次の 2 つは自前で用意しています。

- **JSON の読み書き** → `src/core/Json.cpp`（約 400 行の自前パーサ）
- **文字の表示** → `src/platform/Font.cpp`（手描きの 5x7 ドットフォント）
- **日本語フォントの読み込み** → `src/core/TrueType.cpp`（自前の最小 TrueType
  リーダ。パソコンに入っている日本語フォントを読んで、12px の白黒に
  変換します。漢字もひらがなもそのまま出せます）

日本語フォントが見つからない環境では、内蔵の 8x8 カタカナに自動で
切り替わります（ひらがなはカタカナ表記になります）。
`data/font.ttf`（または `.ttc`）を置けば、好きな書体に差し替えられます。
今どのフォントを使っているかは SETTINGS 画面の下に出ます。

## 実装している内容

**戦闘システム**

- フレーム単位の技データ（発生 / 持続 / 硬直）。フレームは 1 から数え、
  「発生 4F」は **4 フレーム目に最初の攻撃判定が出る** という意味です
  （4 フレーム待ってから 5 フレーム目に出る、ではありません）。
  したがって全体フレームは `(発生 - 1) + 持続 + 硬直` です。

  ```
  発生 4F / 持続 3F / 硬直 7F の技
    1-3F   発生前
    4-6F   攻撃判定      ← 「発生 4F」とはここのこと
    7-13F  硬直          ← 「硬直 7F」＝ 7 フレームぶん続く
    14F    行動可能
    全体フレーム = (4-1) + 3 + 7 = 13F
  ```

- **硬直差はデータに直接書きます**（`hitAdvantage` / `blockAdvantage`）。
  のけぞり時間はそこから自動で計算されるので、
  「表に書いた硬直差」と「実際の挙動」が食い違うことがありません。

  ```
  のけぞり ＝ 硬直差 ＋ (持続 ＋ 硬直)
  硬直差   ＝ 防御側の硬直フレーム数 － 攻撃側の残り全体フレーム数
  ```

  - 前の技のヒット時硬直差 ≧ 次の技の発生 → コンボになる
  - ガード時硬直差の絶対値 ≧ 相手の技の発生 → 確定反撃になる

  どちらも自動テストで、実際に試合を回して 1 フレーム単位で検証しています。
- ヒットストップ / ガードストップ（双方に同時に掛かり、同時に解ける。
  止まっている間は座標・アニメーション・タイマー・制限時間のすべてが停止し、
  入力だけを先行入力として受け付けます。ストップの長さは硬直差に
  影響しません）
- 3 種類の当たり判定（攻撃・食らい・押し合い）を厳密に分離
- 食らい判定は頭・胴・脚の 3 部位に分割（姿勢ごとに形が変わる）
- ガードの種類（上段 / 下段 / 中段 / 投げ）
- のけぞり・ガード硬直・ヒットストップ・ダウン・起き上がり
- ジャンプ攻撃の硬直は空中では消化されず、**着地してから**
  着地硬直（`landingRecovery`）として消化します
- 技のあとは元の姿勢へ戻ります（立ち技なら立ち、しゃがみ技ならしゃがみ）。
  しゃがみガード中でも攻撃ボタンでその姿勢の技が出せます
- キャンセル（コンボ）、カウンターヒット 2 段階
- 超必殺技ゲージ、飛び道具、投げ（距離判定）
- 入力バッファとコマンド技の認識（236 / 623 / 214 / 236236 など）
- 押し合い判定の解決（画面端では端側が動かない）
- 前進の方式をキャラクターごとに選択（ダッシュ ／ キャラ 1 体分の
  ステップ）。前・前 の 2 回入力で発動します

**キャラクターの絵**

- 図形（円・カプセル・多角形）を組み合わせて、その場で描く方式が既定です。
  画像ファイルが 1 枚も無くても遊べます
- `data/sprites/<キャラクターID>/` に絵を置けば、そのキャラクターだけ
  手描きのスプライトで表示されます。姿勢や技ごとにコマを指定でき、
  用意していない姿勢は近いコマ（最後は立ち絵）で代用されるので、
  立ち絵 1 枚からでも始められます。絵を置いていないキャラクターは
  図形描画のままです（[data/sprites/README.md](data/sprites/README.md)）
- `Kakuge --export-sprites` で、今の図形描画をそのままシート画像
  （BMP）と `sprites.json` に書き出せます。それを塗り替えていけば、
  位置合わせで悩まずに自分の絵を入れられます

**画面**

- タイトル / キャラクター選択 / 対戦前演出 / 対戦 / 結果 / 設定 / 操作説明
- キャラクターエディタ（技の数値と当たり判定をゲーム内で編集・保存）。
  表示は日本語で、`L` キーで英語に切り替えられます
- 固定倍率の横スクロールカメラ（間合いの感覚が変わらないよう拡大縮小しません）。
  2 人が離れられる距離の上限を「画面幅 － キャラクター 1 体ぶんの絵」＝ 304 に
  決めてあるので、いちばん離れたときに 2 人の絵の外側が画面の左右の端と
  ちょうど重なります。カメラは常にその範囲へ収めるので、どちらかが
  画面の外に取り残されることがありません。ステージの端まで寄せると、
  壁の面が画面の端にぴったり重なります
- ポーズメニュー、トレーニングモード（自動回復・練習相手の行動固定。
  立ち / しゃがみ / ジャンプ / ガードから選べます）。
  「ガード」は後ろを入れっぱなしにするのではなく、**攻撃が当たる瞬間だけ**
  ガードを入力します。空振りにはガードしないので、間合いの確認や
  下段・中段の使い分けの練習がそのままできます
- 当たり判定の可視化（トレーニング中に `F1`）。技を出している間は
  発生 / 持続 / 硬直と硬直差も数字で出ます

**操作**

キーボードと USB コントローラの両方に対応しています（同時に使えます）。

| | 操作 |
|---|---|
| キーボード | `A`/`D` 移動、`S` しゃがみ、`Space` ジャンプ、`U`/`I`/`O` 弱中強パンチ、`J`/`K`/`L` 弱中強キック |
| 市販パッド | スティック・十字キーで移動、`X`/`Y`/`RB` パンチ、`A`/`B`/`RT` キック、`LB` 投げ |
| 自作コントローラ | ボタン 0-2 パンチ、3-5 キック、6 投げ、ハット・軸で移動 |

自作のレバーレスコントローラ（PKB 32u4 のような ATmega32U4 基板）は
SDL の対応表に載っていないので、ボタン番号をそのまま読みます。
配線した順に 0 番から並んでいれば、そのまま使えます。
詳しくは `src/platform/Gamepad.h` を見てください。

---

**CPU 対戦相手**

人間とまったく同じ入力しか行いません（内部で特別扱いをしていません）。
間合いに応じて、接近・攻撃・ガード・対空・飛び道具を選びます。

```
  core/

    TrueType.*        日本語フォント（TrueType）の読み込み
  engine/             戦闘のルール（SDL2 に一切依存しない）
    Constants.h         共通の定数と寸法の基準
    Boxes.h             当たり判定の四角形
    CharacterStats.h    キャラクターの基本性能
    MoveData.h          技 1 つぶんのデータ
    MoveExecutor.h      技が今どの段階かの計算
    StateMachine.h      状態の管理
    InputSystem.h       入力履歴とコマンド認識
    Fighter.h           キャラクターの本体（一番大きい）
    CPUAI.h             CPU の思考
    BattleSystem.h      試合の進行役
    Projectile.h        飛び道具
    SuperGauge.h        超必ゲージ
    DataManager.h       データの読み書き
    Settings.h          画面設定
  platform/           SDL2 を使う部分（画面と入力）
    Renderer.*          描画の土台（SDL_RenderGeometry）
    Font.*              ドットフォント
    Figure.*            キャラクターの絵（図形で組み立てる）
    Sprite.*            手描きの絵（スプライト）の読み込みと描画
    SpriteExport.*      図形描画をスプライトの型紙に書き出す
    Camera.*            カメラと座標変換
    Hud.*               体力ゲージなどの情報表示
    Game.*              メインループと画面の切り替え
    Screens.cpp         各画面の見た目
    Paths.*             フォルダの場所
    Palette.h           配色
    Editor.*            キャラクターエディタ
    Gamepad.*           USB コントローラの入力
tests/
  EngineTests.cpp     戦闘ロジックの自動テスト（SDL2 不要）
  CameraTests.cpp     カメラとステージ端の自動テスト
  GamepadTests.cpp    コントローラ割り当ての自動テスト（仮想ジョイスティック）
```

`engine/` は SDL2 も Windows も一切使っていません。
だから画面を出さずにテストでき、将来ほかの環境へ移すのも簡単です。

## データを書き換えて遊ぶ

技の性能はすべて `data/moves/ryu/*.json` に入っています。
プログラムを触らずに、テキストエディタでこれを書き換えるだけで調整できます。

```json
{
  "id": "standing_light",
  "name": "立ち弱パンチ",
  "startup": 4,          ← 発生（4 フレーム目に攻撃判定が出る）
  "active": 3,           ← 持続（攻撃判定が出ている長さ＝4〜6F）
  "recovery": 7,         ← 硬直（持続のあと 7 フレームぶん動けない）
  "damage": 300,
  "hitAdvantage": 4,     ← ヒット時硬直差（+4 ＝ 自分が 4F 早く動ける）
  "blockAdvantage": -1,  ← ガード時硬直差（-1 ＝ 相手が 1F 早く動ける）
  "hitbox": [{ "offsetX": 28, "offsetY": -66, "width": 17, "height": 11 }]
}
```

技によって意味を持つ項目もあります。

| 項目 | 対象 | 意味 |
|---|---|---|
| `knockdownFrames` | ダウンさせる技 | 倒れているフレーム数（のけぞりの代わり） |
| `landingRecovery`  | 空中技 | 着地してから動けるようになるまでのフレーム数 |

体力とダメージは 10000 を基準にしています（弱パンチ 300 ＝ 体力の 3%）。

書き換えたら `data` フォルダを `build\bin\data` にコピーし直す
（またはビルドし直す）だけで反映されます。

キャラクターの性能は `data/characters/ryu.json` です。
手描きの絵に差し替える方法は
[data/sprites/README.md](data/sprites/README.md) にまとめてあります。

> ゲーム内で編集した内容や画面設定は、ゲーム本体のフォルダではなく
> `%APPDATA%\Kakuge\` に保存されます。元のデータは書き換わりません。

## 開発中に確認したこと

- Linux（g++ 13 / SDL2 2.30 / CMake 3.28）で同じ `CMakeLists.txt` からビルド確認
- `EngineTests` 158 項目すべて成功（戦闘ロジック・フォント読み込み。
  画面を出さずに実行）
- `CameraTests` 8 項目すべて成功（2 人が常に画面に収まること、ステージの端が
  画面の端と重なることを、画面を出さずに検証）
- `GamepadTests` 14 項目すべて成功（SDL の仮想ジョイスティックを使って、
  実物のコントローラ無しでボタンの割り当てを検証）
- 仮想ディスプレイ上で実際に起動し、タイトル → キャラクター選択 → 対戦 →
  結果まで一通り操作して画面を確認
