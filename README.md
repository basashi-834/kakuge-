# Kakuge — 2D 対戦格闘ゲーム（C++17 + SDL2）

1990 年代のアーケード格闘ゲームを手本にした、2D 対戦格闘ゲームです。
384x224 という当時のアーケード基板と同じ内部解像度で描画し、
それを整数倍に拡大してウィンドウいっぱいに表示します。
ウィンドウの縦横比が違っても、キャンバスの側を広げて合わせるので、
まわりに黒い余白（レターボックス）は出ません。

**ビルドの手順は [BUILD_WINDOWS.md](BUILD_WINDOWS.md) を見てください。**
はじめての方向けに、1 コマンドずつ丁寧に書いてあります。

**中身のしくみは [docs/HOW_IT_WORKS.md](docs/HOW_IT_WORKS.md) にまとめました。**
「ボタンを押してから相手の体力が減るまで」に何が起きているかを、
順番どおりに追いかけた解説です。コードを読む前にここを読むと、
どのファイルを開けばいいかが分かります。

**画像（スプライト）の差し替え方は
[data/sprites/README.md](data/sprites/README.md) です。**

## 決めごと

| 項目 | 内容 |
|---|---|
| 言語 | C++17 |
| ライブラリ | **SDL2 のみ**（2.0.18 以降。`SDL_RenderGeometry` を使用） |
| ビルド環境 | Windows + Visual Studio（MSVC / CMake）。SDL2 は直接DL または vcpkg |
| コメント | 初心者向けに日本語で厚めに |

SDL2 以外のライブラリは一切使いません。そのため、
本来なら外部ライブラリに頼る次の 2 つは自前で用意しています。

- **JSON の読み書き** → `src/core/Json.cpp`（約 400 行の自前パーサ）
- **文字の表示** → `src/platform/Font.cpp`（手描きの 5x7 ドットフォント）
- **日本語フォントの読み込み** → `src/core/TrueType.cpp`（自前の最小 TrueType
  リーダ。パソコンに入っている日本語フォントを読んで、12px の白黒に
  変換します。漢字もひらがなもそのまま出せます）

日本語フォントが見つからない環境では、内蔵の 8x8 カタカナに自動で
切り替わります（ひらがなはカタカナ表記になります）。
`data/font.ttf`（または `.ttc`）を置けば、好きな書体に差し替えられます。
今どのフォントを使っているかは SETTINGS 画面の下に出ます。

## 実装している内容

**戦闘システム**

- フレーム単位の技データ（発生 / 持続 / 硬直）。フレームは 1 から数え、
  「発生 4F」は **4 フレーム目に最初の攻撃判定が出る** という意味です
  （4 フレーム待ってから 5 フレーム目に出る、ではありません）。
  したがって全体フレームは `(発生 - 1) + 持続 + 硬直` です。

  ```
  発生 4F / 持続 3F / 硬直 7F の技
    1-3F   発生前
    4-6F   攻撃判定      ← 「発生 4F」とはここのこと
    7-13F  硬直          ← 「硬直 7F」＝ 7 フレームぶん続く
    14F    行動可能
    全体フレーム = (4-1) + 3 + 7 = 13F
  ```

- **硬直差はデータに直接書きます**（`hitAdvantage` / `blockAdvantage`）。
  のけぞり時間はそこから自動で計算されるので、
  「表に書いた硬直差」と「実際の挙動」が食い違うことがありません。

  ```
  のけぞり ＝ 硬直差 ＋ (持続 ＋ 硬直)
  硬直差   ＝ 防御側の硬直フレーム数 － 攻撃側の残り全体フレーム数
  ```

  - 前の技のヒット時硬直差 ≧ 次の技の発生 → コンボになる
  - ガード時硬直差の絶対値 ≧ 相手の技の発生 → 確定反撃になる

  どちらも自動テストで、実際に試合を回して 1 フレーム単位で検証しています。
- ヒットストップ / ガードストップ（`hitstop` / `guardstop`）。
  技ごとに**別々の値**を設定でき、片方を変えてももう片方は変わりません。
  双方に同時に掛かり同時に解けるので、ストップの長さは硬直差に影響しません。
  止まっている間は座標・アニメーション・タイマー・制限時間のすべてが
  停止し、**入力だけは受け付けます**（ストップ中に入れた必殺技コマンドは、
  解けた瞬間にキャンセルとして成立します）
- 3 種類の当たり判定（攻撃・食らい・押し合い）を厳密に分離
- 食らい判定は頭・胴・脚の 3 部位に分割（姿勢ごとに形が変わる）
- **食らい判定は技ごとにも設定できます**（`hurtboxes`）。技を出している
  間だけ、その技専用の形に差し替わります。足払いで前へ伸ばした脚が
  そのまま「殴られる場所」になるので、伸びた脚を狙って潰す、という
  差し合いが成立します。設定しなければ、これまでどおり姿勢どおりの形です

  ```
  優先順位（上が強い）
    1. frameBoxes の hurtboxes … このフレームだけ差し替え
    2. 技の hurtboxes           … その技の間ずっと差し替え
    3. 姿勢ごとの標準           … 技を出していないときの形
  ```
- ガードの種類（上段 / 下段 / 中段 / 投げ）
- のけぞり・ガード硬直・ヒットストップ・ダウン・起き上がり
- ジャンプ攻撃の硬直は空中では消化されず、**着地してから**
  着地硬直（`landingRecovery`）として消化します
- 技のあとは元の姿勢へ戻ります（立ち技なら立ち、しゃがみ技ならしゃがみ）。
  しゃがみガード中でも攻撃ボタンでその姿勢の技が出せます
- 技中の空中判定（`airborne`）。見た目の Y 座標とは**別**に、
  「何F目から何フレーム空中扱いか」を技ごとに指定できます。
  地面に立って見えていても空中判定にでき（地上投げが当たらない）、
  `UntilLanding` を選べば実際に着地するまで空中のままにもできます
- 前ステップ／前ダッシュと、**独立した設定**のバックステップ／
  バックダッシュ（後ろ・後ろ）。前の数値を変えても後ろは変わりません
- キャンセル（コンボ）。種類ごとに別々の設定を持ちます。

  | 種類 | 内容 |
  |---|---|
  | `special` | 必殺技キャンセル |
  | `super` | 超必殺技キャンセル |
  | `driveRush` | 前・前 で技をキャンセルして踏み込む |
  | `targetCombo` | 通常技から通常技への派生 |

  それぞれに「有効 / 開始F / 終了F / ヒット時 / ガード時 / 空振り時 /
  派生先の技」を設定できます。時間帯は持続中に限らず、発生中でも
  硬直中でも置けます。キャンセルが成立すると、残りの持続・硬直を
  打ち切って次の技の 1F 目へ移ります。
- カウンターヒット 2 段階
- 超必殺技ゲージ、飛び道具、投げ（距離判定）
- 入力バッファとコマンド技の認識（236 / 623 / 214 / 236236 など）
- 押し合い判定の解決（画面端では端側が動かない）
- 前進の方式をキャラクターごとに選択（ダッシュ ／ キャラ 1 体分の
  ステップ）。前・前 の 2 回入力で発動します

**キャラクターの絵**

- 図形（円・カプセル・多角形）を組み合わせて、その場で描く方式が既定です。
  画像ファイルが 1 枚も無くても遊べます
- `data/sprites/<キャラクターID>/` に絵を置けば、そのキャラクターだけ
  手描きのスプライトで表示されます。姿勢や技ごとにコマを指定でき、
  用意していない姿勢は近いコマ（最後は立ち絵）で代用されるので、
  立ち絵 1 枚からでも始められます。絵を置いていないキャラクターは
  図形描画のままです（[data/sprites/README.md](data/sprites/README.md)）
- `Kakuge --export-sprites` で、今の図形描画をそのままシート画像
  （BMP）と `sprites.json` に書き出せます。それを塗り替えていけば、
  位置合わせで悩まずに自分の絵を入れられます

**画面**

- タイトル / キャラクター選択 / 対戦前演出 / 対戦 / 結果 / 設定 / 操作説明
- キャラクターエディタ（技の数値と当たり判定をゲーム内で編集・保存）。
  表示は日本語で、`L` キーで英語に切り替えられます
  - **技の追加 / 複製 / 削除**（削除は確認つき。他の技から派生先として
    参照されている場合は警告し、消えた技への参照も自動で取り除きます）
  - **判定をマウスで編集**: 判定タブで四角形を左ドラッグすると移動、
    四隅・辺のつまみで大きさが変わります。重なっているときはクリックで
    選び直せます。数値欄と画面の四角形は常に同じデータを見ているので、
    どちらで動かしても即座に一致します。座標は 1px 単位（整数）で、
    `G` で目盛りへの吸着（Snap to Grid）、`[` `]` で目盛り幅を変えられます
  - 攻撃判定・食らい判定に加えて、**押し合い判定**も姿勢ごとに編集できます
  - **技ごとの食らい判定**も同じ画面で編集できます（判定タブの「対象」で
    「食らい この技」を選ぶ）。「姿勢の判定をコピー」で標準の形を写して
    から伸ばすのが手早く、姿勢の標準の形と技の攻撃判定が薄く重ねて
    表示されるので、伸ばしすぎ・伸ばし足りないがその場で分かります
  - 判定の色はゲーム内のデバッグ表示（`F1`）とそろえてあります
    （赤＝攻撃 / 緑＝食らい / 青＝押し合い）
  - 技やキャラクターを切り替えても、**保存していない編集は消えません**。
    続けて何個か調整してから、最後に `S` を 1 回押せばまとめて保存されます
- 固定倍率の横スクロールカメラ（間合いの感覚が変わらないよう拡大縮小しません）。
  2 人が離れられる距離の上限を「画面幅 － キャラクター 1 体ぶんの絵」＝ 304 に
  決めてあるので、いちばん離れたときに 2 人の絵の外側が画面の左右の端と
  ちょうど重なります。カメラは常にその範囲へ収めるので、どちらかが
  画面の外に取り残されることがありません。ステージの端まで寄せると、
  壁の面が画面の端にぴったり重なります
- ポーズメニュー、トレーニングモード（自動回復・練習相手の行動固定。
  立ち / しゃがみ / ジャンプ / ガードから選べます）。
  「ガード」は後ろを入れっぱなしにするのではなく、**攻撃が当たる瞬間だけ**
  ガードを入力します。空振りにはガードしないので、間合いの確認や
  下段・中段の使い分けの練習がそのままできます
- 当たり判定の可視化（トレーニング中に `F1`）。技を出している間は
  発生 / 持続 / 硬直と硬直差も数字で出ます

**操作**

キーボードと USB コントローラの両方に対応しています（同時に使えます）。

| | 操作 |
|---|---|
| キーボード | `A`/`D` 移動、`S` しゃがみ、`Space` ジャンプ、`U`/`I`/`O` 弱中強パンチ、`J`/`K`/`L` 弱中強キック |
| 市販パッド | スティック・十字キーで移動、`X`/`Y`/`RB` パンチ、`A`/`B`/`RT` キック、`LB` 投げ |
| 自作コントローラ | ボタン 0-2 パンチ、3-5 キック、6 投げ、ハット・軸で移動 |

自作のレバーレスコントローラ（PKB 32u4 のような ATmega32U4 基板）は
SDL の対応表に載っていないので、ボタン番号をそのまま読みます。
配線した順に 0 番から並んでいれば、そのまま使えます。
詳しくは `src/platform/Gamepad.h` を見てください。

**CPU 対戦相手**

人間とまったく同じ入力しか行いません（内部で特別扱いをしていません）。
間合いに応じて、接近・攻撃・ガード・対空・飛び道具を選びます。

## データを書き換えて遊ぶ

技の性能はすべて `data/moves/ryu/*.json` に入っています。
プログラムを触らずに、テキストエディタでこれを書き換えるだけで調整できます。

```json
{
  "id": "standing_light",
  "name": "立ち弱パンチ",
  "startup": 4,          ← 発生（4 フレーム目に攻撃判定が出る）
  "active": 3,           ← 持続（攻撃判定が出ている長さ＝4〜6F）
  "recovery": 7,         ← 硬直（持続のあと 7 フレームぶん動けない）
  "damage": 300,
  "hitAdvantage": 4,     ← ヒット時硬直差（+4 ＝ 自分が 4F 早く動ける）
  "blockAdvantage": -1,  ← ガード時硬直差（-1 ＝ 相手が 1F 早く動ける）
  "hitbox": [{ "offsetX": 28, "offsetY": -66, "width": 17, "height": 11 }]
}
```

技によって意味を持つ項目もあります。

| 項目 | 対象 | 意味 |
|---|---|---|
| `knockdownFrames` | ダウンさせる技 | 倒れているフレーム数（のけぞりの代わり） |
| `landingRecovery`  | 空中技 | 着地してから動けるようになるまでのフレーム数 |
| `hitstop` / `guardstop` | すべて | ヒット時／ガード時に両者が止まるフレーム数（別々に設定） |
| `airborne` | すべて | 技中の空中判定（`enabled` / `startFrame` / `durationFrames` / `mode`） |
| `hurtboxes` | すべて | 技ごとの食らい判定（下記） |
| `cancels` | すべて | キャンセル設定（4 種類ぶん。下記） |

技ごとの食らい判定は、部位の配列で書きます（姿勢ごとの書き方と同じ形）。

```json
"hurtboxes": [
  { "part": "head",  "offsetX": 0,  "offsetY": -54, "width": 19, "height": 16 },
  { "part": "torso", "offsetX": 0,  "offsetY": -39, "width": 32, "height": 26 },
  { "part": "leg",   "offsetX": 16, "offsetY": -8,  "width": 66, "height": 16 }
]
```

中身を残したまま一時的に切りたいときは、次の形でも書けます。

```json
"hurtboxes": { "enabled": false, "parts": [ ... ] }
```

付属データでは、しゃがみ強キック（足払い）と立ち強キックに入れてあります。
`data/moves/ryu/crouch_heavy.json` を見ると、脚が前へ 49 まで伸びていて、
攻撃判定の先端（53）よりわずかに手前で止めてあるのが分かります。
**攻撃判定より食らい判定が前に出ていると、自分から拳に足を差し出す技**に
なってしまうので、必ず攻撃判定のほうを先に届かせます。

```json
"cancels": {
  "special": {
    "enabled": true, "startFrame": 6, "endFrame": 11,
    "onHit": true, "onBlock": true, "onWhiff": false,
    "allowedMoves": ["fireball"]        ← 空なら制限なし
  },
  "super": { ... }, "driveRush": { ... }, "targetCombo": { ... }
}
```

`hitAdvantage` の欄はエディタで **`D`** と入力するとダウン技になります
（内部では `hitOutcome` と `knockdownFrames` として持ちます）。

体力とダメージは 10000 を基準にしています（弱パンチ 300 ＝ 体力の 3%）。

書き換えたら、ビルドし直すだけで反映されます。

```
cmake --build build --config Release
```

`data` フォルダはビルドのたびに `build\bin\data` へコピーし直されるので、
JSON だけを書き換えたときも、このコマンド 1 つで反映されます
（手でコピーしても構いません）。

キャラクターの性能は `data/characters/ryu.json` です。

## 画像（スプライト）の差し替え

**→ [data/sprites/README.md](data/sprites/README.md) に手順をまとめてあります。**

いちばん短い道すじはこれだけです。

```
Kakuge.exe --export-sprites ryu      ← 今の見た目を型紙として書き出す
```

`data/sprites/ryu/ryu.bmp` と `sprites.json` ができ、ゲームは**もうその絵で
動いています**（見た目は今までと同じ。中身が図形から画像に変わっただけ）。
あとは BMP をお絵かきソフトで開き、コマの上から描き直していくだけです。
1 コマ描き直すたびに、その姿勢だけが新しい絵に変わっていきます。

守ることは 3 つです。

| 決まり | 理由 |
|---|---|
| **BMP** で保存する（PNG 不可） | PNG を読むには別のライブラリが必要になるため（SDL2 だけで動かす決まり） |
| **右向き**で描く | 左向きは自動で反転して表示されます |
| **足の裏の位置を変えない** | ゲームはキャラクターの位置を「足の裏の 1 点」で持っているため。ここがずれると絵が浮きます |

当たり判定は絵とは無関係なので、絵を差し替えても技の性能は変わりません。

> ゲーム内で編集した内容や画面設定は、ゲーム本体のフォルダではなく
> `%APPDATA%\Kakuge\` に保存されます。元のデータは書き換わりません。

## 開発中に確認したこと

- Linux（g++ 13 / SDL2 2.30 / CMake 3.28）で同じ `CMakeLists.txt` からビルド確認
- `EngineTests` 202 項目すべて成功（戦闘ロジック・フォント読み込み。
  画面を出さずに実行）
- `CameraTests` 8 項目すべて成功（2 人が常に画面に収まること、ステージの端が
