# KAKUGE (C++版)

Windows 10/11 でダブルクリックだけで起動する、追加インストール不要のデスクトップ2D対戦格闘ゲームです。
以前の PowerShell + WinForms 版を全面的に **C++ + Win32 API + GDI+** で書き直したバージョンです。

## まず起動したい方へ

`Kakuge.exe` を **Data フォルダ・Audio フォルダと同じ場所に置いたまま**、`Kakuge.exe` をダブルクリックしてください。
インストーラーはありません。コンパイラも .NET も要りません。Windows 10/11 標準の機能だけで動きます。

```
このフォルダ(どこでもOK)
├─ Kakuge.exe   ← これをダブルクリック
├─ Data\        ← キャラクター・技データ(同じ場所に置いておく)
└─ Audio\       ← 効果音を入れる場所(空でもOK、無音のまま動きます)
```

## 「スマートアプリコントロールが安全でない可能性のあるアプリをブロックしました」と出る場合

Windows 11 のスマートアプリコントロール(Smart App Control)が有効な PC では、コード署名されていない
実行ファイル(この Kakuge.exe も該当)は一律にブロックされます。SmartScreen の警告と違い、回避ボタンは
ありません。ソースコードやビルド方法の問題ではなく、対処は次のいずれかです。

1. **スマートアプリコントロールをオフにする**: Windows セキュリティ → アプリとブラウザー コントロール →
   スマートアプリコントロールの設定 → 「オフ」。一度オフにすると Windows を初期化しない限り再度オンには
   できないので、ご自身の開発・テスト用 PC で使う前提の選択肢です。Microsoft 自身、スマートアプリ
   コントロールは開発者向けの機能ではないとしており、自作アプリを継続的にテストする PC ではこれが定石です。
2. **コード署名する**: 認証局発行のコード署名証明書(OV/EV)で署名すれば通ります(自己署名は不可)。証明書を
   用意できる場合は `signtool sign` をビルド手順に組み込めます。
3. 評価モードまたはオフの環境で実行する。

それまで動いていたのに急に出るようになった場合は、スマートアプリコントロールが「評価モード」から自動的に
「オン」へ切り替わったのが原因です(評価モード中は Windows が利用状況を見て自動判断します)。

### 「自分でコンパイルすれば回避できる?」

**おそらく回避できません。** スマートアプリコントロールは「その実行ファイルがどこで作られたか」ではなく、
「その実行ファイル自体が信頼された証明書で署名されているか」「そのファイルのハッシュが Microsoft の
評価データベース(Intelligent Security Graph)で既知の安全なものか」で判定します。自分でビルドした
バイナリは署名が無く、ハッシュも生成したてで未知なので、ダウンロードした場合と同じ条件になります。

ただし検証自体は数分で済みますし、ソースからビルドできること自体に別の利点(中身を確認できる、
自由に改造できる)もあるので、下の「ソースコードから再ビルドしたい場合」の手順を用意してあります。
なお、コンパイラ(Visual Studio Build Tools / MSYS2)自体は署名済みなので、インストールは問題なく通ります。

## なぜ C++ に切り替えたか

前回の PowerShell + WinForms 版は「追加インストール不要」という制約は満たしていましたが、実機で
文字コード起因のエラー・イベントハンドラのクロージャ問題・例外処理の呼び出し順序エラーなど、
スクリプト言語ならではの実行時トラブルが繰り返し発生しました。

C++ + Win32 + GDI+ に切り替えることで、
- **静的リンクした単一の `.exe`** として配布でき、PowerShell の文字コード/実行ポリシー問題が原理的に発生しない
- コンパイル時に多くのミスを検出できる(実際、この後の「テストについて」で述べる通り、実行前にいくつかのバグを検出・修正できました)
- 依存する DLL は `gdiplus.dll` / `kernel32.dll` / `user32.dll` / `shell32.dll` / `msvcrt.dll` / `winmm.dll` のみで、
  すべて **Windows 10/11 に最初から入っているシステムDLL** です。追加のランタイム(Visual C++ 再頒布可能パッケージ等)は一切不要です。

という利点があります。実行ファイルは Linux 上の開発環境で **mingw-w64 (`x86_64-w64-mingw32-g++`)** を使ってクロスコンパイルしており、
あなたの PC 側では一切コンパイル作業をする必要はありません。

## 動作確認について(重要)

このセッションは Linux サンドボックス上で開発しているため実機の Windows がありません。そこで今回は
**Wine + Xvfb(仮想ディスプレイ)を使い、実際に `.exe` を起動してスクリーンショットを撮りながら検証しました。**
前回の PowerShell/WinForms 版では UI 層は一度も実行できず「構文チェックのみ」でしたが、今回はタイトル画面から
キャラクターセレクト→VS画面→対戦→ポーズメニュー→リザルト→設定画面→キャラクターエディター(新規キャラ作成含む)まで、
実際にクリック・キー入力をシミュレートして一通り動作させ、その過程で **実際に3件のバグを検出して修正しました**:

1. Wine 環境にフォントが一切無く `Segoe UI` が解決できず文字が全く描画されない問題
   → `Segoe UI` が見つからない場合は GDI+ の汎用サンセリフ体にフォールバックするよう修正(実機なら通常 `Segoe UI` が使われます)
2. キャラクターエディターで「+ NEW CHARACTER」を押すと、裏にある編集フォームのラベルが隠れずに重なって表示される問題を修正
3. 新規キャラクター作成後、キャラクター選択コンボボックスが新しいキャラクターを選択しない問題を修正
4. **画面のチラつき**(実機での動作確認で報告いただいたもの): 毎フレーム GDI+ の描画命令をウィンドウの実画面に直接
   発行していたため、1フレームぶんの描画が完了する前の途中経過が見えてチラついていました。オフスクリーンの
   ビットマップに1フレームぶんすべて描いてから、完成した画像を一度だけ画面に転送する「ダブルバッファリング」
   方式に修正し、解消しました。これはスクリーンショット1枚を撮る検証方法では気づけない種類の不具合で、
   実機で実際に動かしていただいたおかげで見つかりました。

今回追加した機能(キャラクター拡大、6ボタン化、練習モード、エディターの見た目統一)についても、
同じくWine+Xvfb上で実際に操作して確認しています。特にキャラクター拡大に伴い判定枠のサイズだけ
そのままだと当たり判定が視覚とズレる不具合、CPU AIの間合い判定の閾値が新しいサイズに合わず
攻撃してこなくなる不具合(ロジックのテストスイートで検出)があり、いずれもこの検証中に発見・修正
してから出荷しています。

ただし、Wine は完全な Windows 互換環境ではありません(このテスト環境には日本語フォントも一切無いため、
キャラクターエディターの技名ドロップダウンで日本語が「□□□」のように表示される場面がありましたが、これは
Wine 側にフォントが無いことが原因と判断しています。実機の Windows には日本語フォントが標準で入っているため
再現しない可能性が高いですが、**実機でも念のため技名の表示だけは確認してください**)。
何か表示が崩れている・操作できない箇所があれば教えてください。

## プロジェクト構成

```
cpp-game/
├─ Kakuge.exe          配布用の実行ファイル(ビルド済み)
├─ Data/                 キャラクター・技データ(JSON)
│   ├─ characters/ryu.json
│   ├─ moves/ryu/*.json (12技 - 波動拳/昇龍拳/竜巻旋風脚/超必殺技を含む)
│   └─ match_rules.json  (ラウンド時間などのルール設定)
├─ Audio/                効果音を置く場所(空でもOK、無音のまま動作)
├─ README.md             このファイル
└─ src/                  C++ ソースコード一式(実行には不要、改造・再ビルド用)
    ├─ engine/            ゲームロジック本体(Windows API に一切依存しない)
    │   ├─ Constants.h / Boxes.h / CharacterStats.h / MoveData.h
    │   ├─ MoveExecutor.h / StateMachine.h / SuperGauge.h / InputSystem.h
    │   ├─ Fighter.h / Projectile.h / CPUAI.h / BattleSystem.h
    │   ├─ DataManager.h (JSON 読み書き) / Settings.h (解像度設定)
    ├─ platform/          Win32 / GDI+ 描画・ウィンドウ・入力
    │   ├─ WinMain.cpp    エントリポイント、ウィンドウ・メッセージループ・音声再生
    │   ├─ App.h/.cpp     画面遷移・ゲームループ・入力集約
    │   ├─ Screens.cpp    Title/CharacterSelect/VS/Game/Result/Settings 画面
    │   ├─ Editor.cpp     キャラクターエディター(独自描画UI、ネイティブコントロール不使用)
    │   ├─ Draw.h/.cpp    GDI+ 描画ヘルパー(図形キャラ・HUD・バー等)
    │   ├─ HudSkin.h/.cpp HUD の画像スキン読み込み(Data/hud/)
    │   ├─ Sprites.h/.cpp キャラクターのスプライト画像読み込み(Data/sprites/)
    │   └─ Layout.h / Palette.h  座標変換・配色
    ├─ tests/EngineTests.cpp  ゲームロジックのユニットテスト(53項目)
    ├─ third_party/nlohmann/  JSON ライブラリ(ヘッダオンリー、同梱)
    ├─ build_windows.sh   MinGW-w64 ビルド(Linux クロス / MSYS2 どちらでも)
    ├─ build_windows_msvc.bat  Visual Studio (MSVC) ビルド用バッチ
    └─ build_linux_tests.sh  ロジックテストのネイティブビルド・実行スクリプト
```

**engine/ と platform/ を分離している理由**: engine/ 配下は Windows 系ヘッダを一切 `#include` していない、
プラットフォーム非依存の C++17 コードです。そのため Linux 上でも普通の `g++` でそのままコンパイル・実行でき、
`tests/EngineTests.cpp` によるロジックの自動テストが(Wine やクロスコンパイルなしで)可能になっています。
Win32 API・GDI+ に依存する部分は platform/ にすべて隔離されています。

## テストについて

`src/tests/EngineTests.cpp` は状態機械・判定・ガード・コマンド入力・キャンセル猶予・データ保存/読込・
新規キャラクター作成・当たり判定仕様(GameSpec)など **53項目** を検証する自動テストです(旧 PowerShell 版のテストを1:1で C++ に移植し、
新機能のテストを追加したもの)。開発中、Linux 上で毎回このテストを実行し、**53/53 成功**を確認しています。

```
cd src
./build_linux_tests.sh
```

## 操作方法

6ボタン方式(パンチ3種・キック3種)です。

| キー | 動作 |
|---|---|
| A / D | 左右移動 |
| S | しゃがみ |
| Space | ジャンプ |
| U / I / O | 弱 / 中 / 強パンチ (LP/MP/HP) |
| J / K / L | 弱 / 中 / 強キック (LK/MK/HK) |
| U+J同時 (LP+LK) | 投げ |
| 波動拳・昇龍拳・超必殺技 | コマンド入力 + パンチ系ボタンいずれか |
| 竜巻旋風脚 | コマンド入力 + キック系ボタンいずれか |
| ガード | 相手と逆方向を入力しっぱなし |
| Esc | ポーズメニュー |
| F1 | デバッグ表示切替(判定枠・状態・フレーム数など) |

## 画面レイアウト・当たり判定の基準値(GameSpec)

内部解像度 384x224 を基準に、画面構成と当たり判定はすべて `engine/Constants.h` の `GameSpec` に
まとめた整数定数から導出しています(画像サイズから判定を取る実装は一切ありません。スプライトは見た目だけ、
判定は独立した矩形データです)。

| 項目 | 値 |
|---|---|
| 内部解像度 | 384 x 224(整数倍でニアレストネイバー拡大) |
| 接地ライン GROUND_Y | 189(画面高の84.4%) |
| キャラクター見た目 | 高さ88(39.3%)、幅は約55を目標(スプライト作画領域 75x90) |
| 初期位置 | P1 中心X=116(30%)、P2 中心X=268(70%)、中心間152 |
| 上部HUD / 下部ゲージ | 30px / 18px |
| Pushbox(押し合い専用) | 立ち 30x72、しゃがみ 32x48、空中 28x52(空中は胴体中心基準) |
| Hurtbox(喰らい) | 立ち: 頭18x16 + 上半身30x30 + 下半身28x42(外周 30x88)。しゃがみ・空中も3分割 |
| Hitbox(攻撃) | 技ごと・発生フレーム中のみ。弱P 16x10 / 強P 20x12 / 弱K 18x10 / 強K 24x14 / 屈弱K 20x8 |
| 投げ | Hitboxではなく中心間距離 28px 以内・双方地上・投げ可能状態で成立 |

- Pushbox 同士が重なったら半分ずつ押し戻し、片方が画面端(ステージ端)にいる場合はもう片方が全量を吸収します
- Hitbox / Hurtbox / Pushbox の X 座標は向き(FacingDirection)で自動反転します(データは1セットのみ)
- 技ごとに JSON の `frameBoxes` でフレーム範囲を指定して Pushbox / Hurtbox[] / Hitbox[] を差し替えられます
  (例: 対空技中に腕側の Hurtbox を縮める)。現時点ではエディターUIは未対応で、JSON直接編集です
- 判定矩形は整数px、描画位置も最終的に整数pxへスナップします(移動計算内部は小数)
- 練習モード中に **F1** で判定表示: Pushbox=青 / Hurtbox=緑 / Hitbox=赤 / 投げ範囲=黄
  (半透明の塗り + 枠線、Pushbox は破線。飛び道具の Hitbox も表示。画面下に色の凡例)

## 見た目の差し替え(画像スキン)

- **キャラクター**: `Data/sprites/<id>/` に PNG を置くとポーズごとに差し替わります(詳細は同フォルダの README.txt)。
  画像が無いポーズは、図形で構成した内蔵キャラクター(頭・胴・カプセル状の手足、約 55x88px)で描画します。
- **HUD**: `Data/hud/` に PNG を置くと HP バー枠・ポートレート・タイマー枠・スーパーゲージ枠が差し替わります。
  HP/ゲージの中身は `hp_unit.png`(1% ぶんのスプライトを 100 個並べ、残り % の個数だけ描く方式)か
  `hp_fill.png`(満タン画像を割合で切り出す方式)のどちらかで指定できます。P2 側は自動で左右反転。
  無い要素はプログラム描画のままです(詳細は `Data/hud/README.txt`)。

## キャラクターエディター

タイトルの CHARACTER EDIT から開きます。Windows のネイティブ部品(WinForms/Win32 コントロール)は
一切使わず、ゲーム本体と同じ GDI+ 描画で作った独自 UI です(1 回の描画で画面全体を描き、操作したときだけ
再描画するので軽快に動きます)。

- 入力欄はクリックしてキー入力。Backspace / Delete / ←→ / Home / End、Tab で次の欄、Enter/Esc で確定
- プルダウンはクリックで一覧を開き、項目をクリックで選択(項目が多いときはホイールでスクロール)
- 発生/持続/硬直などのフレーム数は 0〜99 の範囲
- 保存結果などのメッセージはヘッダー左に数秒表示されます(ダイアログは出ません)
- 右上の JP/EN で表示言語を切り替え

## 画面構成

- **タイトル画面**: GAME START / TRAINING MODE / CHARACTER EDIT / SETTINGS / EXIT
- **キャラクターセレクト画面**: プレイヤー→CPU(または練習相手)の順にキャラクターを選択。ポートレート・
  POWER/STAMINA/SPEED/REACH のステータスバー付き。「+ ADD CHARACTER」タイルからその場で新規キャラを作成可能。
- **VS画面**: 対戦カード演出(対戦モードのみ。練習モードは選択後すぐ対戦画面へ)。任意のキーでスキップできます。
- **対戦画面**: HP/超必殺ゲージ/ラウンドタイマー/コンボカウンター表示。
- **ポーズメニュー**(Escで開閉): 対戦モード/練習モードで内容が変わります。
  - 対戦モード: RESUME / GIVE UP → TITLE のみ(相手は常に本物のCPU)。
  - 練習モード: RESUME に加え、**CPU側(P2)の挙動を CPU / 立ち / しゃがみ / ジャンプ の4種類に切り替え**、
    **AUTO HEAL のON/OFF切替**、**RESET HP**(両者のHPを即座に全回復)、GIVE UP → TITLE。
- **練習モード**(新規): タイトルの「TRAINING MODE」から入ります。ラウンドタイマーは無制限(表示は∞)、
  どちらのKOも対戦を終了させません。AUTO HEALをONにすると練習相手のHPが自動で回復し続け、
  ダウンしてもすぐ起き上がります(何度でもコンボを練習できます)。OFFにすると通常通りダメージが
  蓄積したままになるので、RESET HPで任意のタイミングで全回復できます。
- **リザルト画面**: 勝敗・MAX COMBO・TIME LEFT・DAMAGE TAKEN。REMATCH / CHARACTER SELECT / TITLE。
- **設定画面**: 解像度を 320x200 〜 1920x1080 の9段階(4:3・16:9・16:10)から選択できます。
  画面・HUD・キャラクター(人型ライン画)はすべて仮想キャンバス(1280x720)上に描画し、選んだ解像度に
  一括で拡大縮小(レターボックス)しているため、**どの解像度を選んでもキャラクターや文字が正しい比率で表示されます**。
- **キャラクターエディター**: 赤いヘッダーバーと、対戦画面と共通の赤/白ボタンデザインに統一しました。
  既存キャラの基礎ステータス・技のフレームデータ(発生/持続/硬直/ダメージ/ヒット硬直/ガード硬直/
  ヒットストップ)を編集・保存できます。技選択ドロップダウンは技IDではなく **技の表示名**
  (「昇龍拳」等)で表示されます。「+ NEW CHARACTER」から新規キャラクターをその場で作成でき、
  既存キャラの技構成をテンプレートとして複製して土台にします。

## 今回のPowerShell版からの主な変更点

1. 実装言語を PowerShell から **C++17** に全面移植(ロジックは1:1で移植、挙動は変えていません)
2. 配色を暗いチャコール基調から、参考画像に合わせた **白/赤/黒の明るいテーマ** に変更
3. **キャラクターセレクト画面**・**VS画面** を新規追加
4. ポーズメニューに **CPU/立ち/しゃがみ/ジャンプ の切替**(練習用ダミーモード)を追加
5. キャラクターエディターの技ドロップダウンを **技名表示** に修正(以前はファイル名がそのまま出ていました)
6. キャラクターエディターから **新規キャラクターをその場で作成** できる機能を追加(既存キャラの技構成を複製)
7. **設定画面**を新規追加し、解像度を 320x200 ~ 1920x1080(4:3/16:9)の範囲で変更可能に。
   キャラクター・HUD含め全画面が解像度に応じて自動スケーリングされます
8. HUD に **コンボカウンター**(N HIT COMBO)を追加、リザルト画面に MAX COMBO を表示

   コマンド入力+パンチ系ボタンいずれか、竜巻旋風脚はコマンド入力+キック系ボタンいずれかで発生します。
   投げは LP+LK(U+J)同時押しに変更しました。
3. **竜巻旋風脚を追加**(新規必殺技、`214`+キック)。
4. **不具合修正**: 波動拳などの必殺技を出した際、歩き/ダッシュの慣性が残ってキャラクターが
   前進し続けてしまう不具合を修正(技を出す瞬間に地上での横方向速度をリセットするようにしました)。
5. **対戦モードと練習モードを分離**: 詳細は上の「画面構成」を参照してください。
6. **キャラクターエディターの見た目を対戦画面と統一**(赤いヘッダーバー、赤/白のボタンデザイン)。

## 今回のスコープ外・簡略化した点

- **キャラクターエディターで編集できる項目**: 基礎ステータス全般と、技の
  表示名/発生/持続/硬直/ダメージ/ヒット硬直/ガード硬直/ヒットストップ に対応しています。
  判定枠のサイズ・オフセット、キャンセルルート、タグ、無敵時間、飛び道具パラメータ等の高度な項目は
  今回のフォームでは編集できません。必要な場合は `Data\moves\<キャラID>\<技ID>.json`(または編集後は
  `%APPDATA%\Kakuge\moves\<キャラID>\`)を直接テキストエディタで編集してください。スキーマは
  旧PowerShell版と同一です。
- **キャラクター固有のイラスト**は用意していません(全キャラクター共通のライン画人型モデルで、
  頭身・カラーのみキャラごとに変わります)。新規作成したキャラクターも同じ人型モデルを使います。
  いただいた参考画像(RAY/KENJIのイラスト)は、注釈(矢印・寸法線・見出しテキスト)が背景ごと
  一枚の画像として合成された「解説用の比較図」で、そのままゲーム内のキャラクター素材として
  切り出せる形にはなっていなかったため、今回は「サイズ・比率の参考」として数値だけを反映し、
  絵そのものは差し替えていません。透過済みの単体イラスト素材(背景・注釈なし)があれば、
  ライン画の代わりに使うことも可能です。
- **効果音**はファイルを同梱していません。`Audio\attack.wav` / `hit.wav` / `block.wav` / `ko.wav`
  (非圧縮PCM .wav)を置くと自動的に再生されます(旧PowerShell版と同じ仕組みです)。
- キャラクターセレクト画面の「?」プレースホルダー演出(参考画像にあった、未解禁キャラのような表示)は
  実装していません。表示されるのは実際に存在するキャラクターと「+ ADD CHARACTER」のみです。

## 保存データの場所

キャラクター・技の編集内容、新規作成したキャラクター、画面解像度の設定は、いずれも
`%APPDATA%\Kakuge\` 以下に保存されます(`Kakuge.exe` と同じフォルダの `Data\` は書き換えません)。
アンインストールしたい場合は `Kakuge.exe` とその周辺フォルダを削除し、
`%APPDATA%\Kakuge\` フォルダも削除してください。

## ソースコードから再ビルドしたい場合(Windows でのビルド手順)

同梱の `Kakuge.exe` はそのままで動きます(ビルドは必須ではありません)。ソースを変更したい場合や、
自分の PC でコンパイルして確かめたい場合は、以下のどちらかの方法でビルドできます。
どちらも同じ `src/` 以下のソースから同じものが作れます。ビルド後は生成された `Kakuge.exe` の隣に
`Data`(と、音を鳴らすなら `Audio`)フォルダを置いてください。

### 方法A: Visual Studio Build Tools を使う(Windows・無料・おすすめ)

Microsoft 公式の C++ コンパイラです。「何を入れればいいか分からない」場合はこれを選んでください。

**手順1. コンパイラを入れる**

1. https://visualstudio.microsoft.com/ja/downloads/ を開きます。
2. ページを下の方までスクロールし、「**Visual Studio のツール**」(または "Tools for Visual Studio")
   というセクションを開きます。上部にある大きな「Visual Studio Community」ボタンではありません
   (そちらでも構いませんが、容量が大きくなります)。
3. その中の「**Build Tools for Visual Studio 2022**」の「ダウンロード」を押します。
4. ダウンロードした `vs_BuildTools.exe` を実行します。
5. インストーラーが開いたら、**「C++ によるデスクトップ開発」** にチェックを入れて「インストール」。
   これが一番重要です。ここにチェックが無いとコンパイラ本体が入りません。
   (ダウンロード量は数GBあります。時間がかかります)

**手順2. 専用のコマンドプロンプトを開く**

スタートメニューを開き、`x64 Native Tools` と入力して
**「x64 Native Tools Command Prompt for VS 2022」** を起動します。

> 通常の「コマンドプロンプト」や PowerShell ではコンパイラにパスが通っておらず、
> `cl.exe が見つかりません` というエラーになります。必ずこの専用プロンプトを使ってください。

**手順3. ソースのフォルダへ移動する**

エクスプローラーで zip を展開したフォルダの中の `src` フォルダを開き、
アドレスバーをクリックしてパスをコピーします。プロンプトで次のように打ちます
(`cd /d` の後にスペースを空けて、コピーしたパスを貼り付け、末尾に `\src` を付けます)。

```bat
cd /d "C:\Users\あなたの名前\Downloads\Kakuge_v22_source\src"
```

**手順4. ビルドする**

```bat
build_windows_msvc.bat
```

1〜2分ほどで終わり、`Built build\Kakuge.exe` と表示されれば成功です。
`Data` フォルダの隣にも自動でコピーされるので、そのままダブルクリックで遊べます。

### 方法B: MSYS2 + MinGW-w64 を使う(Windows)

配布版 `Kakuge.exe` とまったく同じコンパイラで作る方法です。Visual Studio より軽量ですが、
Unix 風のパス表記(`/c/Users/...`)に慣れが必要です。

1. https://www.msys2.org/ からインストーラーを入手して実行します(既定の設定のままで構いません)。
2. スタートメニューから「**MSYS2 MINGW64**」を起動します(MSYS2 UCRT64 等ではなく MINGW64)。
3. コンパイラを入れます。

```bash
pacman -S --needed mingw-w64-x86_64-gcc
```

4. ソースのフォルダへ移動してビルドします。`C:\Users\...` は `/c/Users/...` と書きます。

```bash
cd /c/Users/あなたの名前/Downloads/Kakuge_v22_source/src
./build_windows.sh
```

`build/Kakuge.exe` が生成されます。`Data` フォルダの隣にコピーして実行してください。

### 方法C: Linux から クロスコンパイル(この配布版を作っている方法)

```bash
sudo apt install mingw-w64      # 環境に応じて
cd src
./build_windows.sh              # build/Kakuge.exe が生成されます
./build_linux_tests.sh          # エンジンのテスト(Windows 不要、Linux 上で実行)
```

### ビルドに必要なもの

- C++17 対応コンパイラ(MSVC / MinGW-w64 GCC)
- Windows SDK(Build Tools に同梱。GDI+ / Win32 API を使用)
- 外部ライブラリの追加取得は不要です。JSON ライブラリ(nlohmann/json)は `src/third_party/` に同梱済みで、
  それ以外の依存はありません。
