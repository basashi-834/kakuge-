# 画像（スプライト）の差し替え方

このフォルダに絵を置くと、図形で組み立てたキャラクターの代わりに
その絵が使われます。置かなければ、これまでどおり図形で描かれます。

置き場所は **キャラクター ID ごとのフォルダ** です。

```
data/sprites/ryu/sprites.json   ← どのコマがどの姿勢かを書く
data/sprites/ryu/ryu.bmp        ← 絵をまとめた 1 枚のシート画像
```

`%APPDATA%\Kakuge\sprites\ryu\` に同じものを置くと、そちらが優先されます
（元のデータを触らずに自分の絵を試したいときに使ってください）。

---

## 何が、どうなって、こうなるのか（仕組み）

差し替えの手順を覚える前に、絵が画面に出るまでの道すじを見ておきます。
ここが分かっていれば、うまく出ないときに「どこを直せばいいか」が
自分で分かります。

```
 ① data/sprites/ryu/sprites.json        「絵の説明書」
        │  どの画像を使うか / 1 コマの大きさ / どのコマがどの姿勢か
        ↓
 ② data/sprites/ryu/ryu.bmp             「絵そのもの（1 枚のシート）」
        │  格子状に並んだコマを、番号で切り出して使う
        ↓
 ③ 起動時に読み込む   … src/platform/Sprite.cpp の LoadAll()
        │  読めなければ何も言わずに図形描画のまま（ゲームは落ちません）
        ↓
 ④ 毎フレーム、コマを 1 つ選ぶ … PickFighterCell()
        │  「今この人は しゃがみ中 → crouch のコマ」というように、
        │  キャラクターの状態からアニメの名前を決めて選びます
        ↓
 ⑤ 画面に描く … DrawSpriteCell()
           コマの中の「足元の点（originX/originY）」を、
           キャラクターの足元の座標に重ねて描きます
```

**大事なのは ⑤ です。** ゲームはキャラクターの位置を
「足の裏の 1 点」だけで持っています。絵のどこが足の裏なのかは
ゲームには分からないので、`sprites.json` の `originX` / `originY` で
教えます。ここがずれていると、その姿勢のときだけ絵が浮いたり沈んだり
します（**絵が浮く原因のほとんどはこれです**）。

なお、**当たり判定は絵とはまったく無関係**です。判定はキャラクター
エディタで決めた四角形のままなので、絵を差し替えても強さは変わりません。

## 手順（いちばん簡単なやり方）

絵を 1 枚も持っていなくても大丈夫です。**今の図形描画をそのまま
「型紙」として書き出し**、その上から描き直すのが最短です。

### 手順 1: 型紙を書き出す

コマンドプロンプトで、`Kakuge.exe` のあるフォルダ（`build\bin`）へ移動して:

```
Kakuge.exe --export-sprites          全キャラクターぶん
Kakuge.exe --export-sprites ryu      ryu だけ
```

`data/sprites/<ID>/` に、次の 2 つができます。

| できるもの | 中身 |
|---|---|
| `<ID>.bmp` | 全部の姿勢が格子状に並んだ 1 枚の画像 |
| `sprites.json` | どのコマがどの姿勢かを書いた説明書 |

### 手順 2: そのまま起動して確かめる

もう絵として表示されています。見た目は今までと同じですが、
中身は「図形」から「画像」に変わっています。
**ここまでで、差し替えの土台は完成しています。**

### 手順 3: BMP をお絵かきソフトで開く

Windows なら「ペイント」でも開けます（無料の Krita や GIMP、
アイビスペイント等でも構いません）。

### 手順 4: コマを 1 つ、上から描き直す

まずは立ち姿（`idle` の 1 コマ目、左上のコマ）だけで十分です。

守ることは 2 つだけです。

1. **コマの枠（格子）からはみ出さない**
2. **足の裏の位置を変えない**（枠の左右中央・上から 104 ピクセル目）

背景は **マゼンタ（R255 G0 B255）** のままにしてください。
この色の部分が透明として抜かれます。

### 手順 5: BMP のまま上書き保存する

PNG ではなく **BMP（24bit または 32bit）** で保存します。
PNG が使えないのは、読むのに SDL_image という別のライブラリが必要に
なるからです（このゲームは SDL2 だけで動く決まりです）。

### 手順 6: ゲームを起動し直す

描き直したコマの姿勢だけが、新しい絵に変わっています。
あとは手順 4〜6 を繰り返して、1 コマずつ置き換えていけば完成です。

> **元に戻したいとき**は `data/sprites/<ID>/` フォルダを削除してください。
> 絵が 1 枚も無ければ、自動的に図形描画へ戻ります。

## 自分で用意した絵を使いたい場合

型紙を使わず、最初から自分のシート画像を置くこともできます。
`data/sprites/<キャラクターID>/` に BMP を置き、同じフォルダに
`sprites.json` を自分で書きます（書き方は下の「sprites.json の書き方」）。

最低限これだけ書けば動きます（立ち絵 1 枚だけの例）。

```json
{
    "sheet": "myryu.bmp",
    "cellWidth": 160,
    "cellHeight": 136,
    "columns": 8,
    "originX": 80,
    "originY": 104,
    "animations": {
        "idle": { "cells": [0] }
    }
}
```

`originX` / `originY` は「コマの左上から数えて、足の裏がどこか」です。
上の例は「左から 80、上から 104 の点が足の裏」という意味になります。

---

## うまくいかないときは

| 症状 | 原因と直し方 |
|---|---|
| 絵がまったく出ない（図形のまま） | `sprites.json` かシート画像が見つかっていません。フォルダ名が**キャラクター ID と同じ**か確認してください（`data/sprites/ryu/`）。JSON の書き間違い（カンマ抜けなど）でも読み込みに失敗します |
| 絵が宙に浮く／地面にめり込む | `originY` がずれています。型紙のままなら 104 です |
| 左を向くと位置がずれる | `originX` がコマの左右中央になっていません。**絵は必ず右向きで描いてください**（左向きは自動で反転されます） |
| 背景のマゼンタが残る | 色が微妙に違います。スポイトで確認して、ぴったり R255 G0 B255 にしてください。または `"transparent": null` にして画像側の透明度を使ってください |
| 一部の姿勢だけ図形に戻る | 図形には戻りません。用意していない姿勢は、下の代用表にしたがって近いコマが使われます |
| 保存したのに変わらない | `data` を書き換えたら、ビルドし直す（`cmake --build build --config Release`）か、`build\bin\data` に直接置いてください |

## 画像の決まり

| 項目 | 内容 |
|---|---|
| 形式 | **BMP**（24bit / 32bit）。SDL2 本体だけで読めるのが理由です |
| 透明 | 既定はマゼンタ（255, 0, 255）。その色の部分が抜けます |
| 並べ方 | 左上から右へ、`columns` 個で次の段へ（格子状） |
| 向き | **必ず右向きで描く**。左向きは自動で反転して表示されます |

PNG は使えません（SDL_image という別のライブラリが必要になるため）。
お絵かきソフトの「名前を付けて保存」で BMP を選んでください。

## sprites.json の書き方

```json
{
    "sheet": "ryu.bmp",
    "transparent": [255, 0, 255],
    "cellWidth": 160,
    "cellHeight": 136,
    "columns": 8,
    "originX": 80,
    "originY": 104,
    "stateTint": true,
    "animations": {
        "idle":   { "cells": [0, 1, 2, 3], "hold": 8 },
        "crouch": { "cells": [4] },
        "punch":  { "cells": [12, 13, 14], "mode": "phase" },
        "move:fireball": { "cells": [30, 31, 32], "mode": "phase" }
    }
}
```

### 全体の設定

| キー | 意味 |
|---|---|
| `sheet` | シート画像のファイル名（この JSON と同じフォルダ） |
| `transparent` | 透明にする色。`null` と書くと画像の透明度をそのまま使います |
| `cellWidth` / `cellHeight` | 1 コマの大きさ |
| `columns` | 1 段に何コマ並んでいるか |
| `originX` / `originY` | コマの中での足元の位置 |
| `stateTint` | ガード中を青く、食らい中を赤く染めるか（既定 `true`）。絵の色をそのまま出したいときは `false` |

### アニメーション 1 本の設定

| キー | 意味 |
|---|---|
| `cells` | 使うコマの番号（左上が 0、右へ 1, 2, …） |
| `frames` | 番号ではなく切り出し位置を直接書く場合（`x` `y` `w` `h` `originX` `originY`）。大きさの違うコマを混ぜたいとき |
| `hold` | 1 コマを何フレーム表示するか（既定 4） |
| `loop` | 最後まで行ったら先頭へ戻るか（既定 `true`） |
| `mode` | `"time"`（既定・時間で進む）か `"phase"`（技の段階に合わせる） |

`"mode": "phase"` は技むけです。コマを 3 つ書くと、
**発生 → 1 つ目、持続 → 2 つ目、硬直 → 3 つ目** が表示されます。
技のフレーム数（`data/moves/*.json` の `startup` / `active` / `recovery`）を
あとから変えても、絵と動きがずれません。

## 用意できる姿勢の名前

必要なものだけ書けば大丈夫です。用意していない姿勢は、
下の「代わりに使うもの」の順に降りていき、最後は必ず `idle` になります
（つまり **立ち絵 1 枚だけでも動きます**）。

| 名前 | いつ使われるか | 無いときの代わり |
|---|---|---|
| `idle` | 立ち | （最後の受け皿） |
| `walk_forward` | 前進 | `walk` → `idle` |
| `walk_backward` | 後退 | `walk` → `idle` |
| `crouch` | しゃがみ | `idle` |
| `jump` | ジャンプ中 | `idle` |
| `block` | 立ちガード | `idle` |
| `block_crouch` | しゃがみガード | `block` → `crouch` → `idle` |
| `hitstun` | 食らい（地上） | `idle` |
| `hitstun_air` | 食らい（空中） | `hitstun` → `jump` → `idle` |
| `throw` | 投げられ中 | `hitstun` → `idle` |
| `knockdown` | ダウン | `dead` → `hitstun` → `idle` |
| `wakeup` | 起き上がり | `crouch` → `idle` |
| `dead` | KO | `knockdown` → `hitstun` → `idle` |
| `punch` / `kick` | 立ち技 | `idle` |
| `crouch_punch` / `crouch_kick` | しゃがみ技 | `punch` / `kick` → `idle` |
| `jump_punch` / `jump_kick` | 空中技 | `punch` / `kick` → `idle` |
| `move:<技のID>` | その技だけの専用の絵 | 上の姿勢＋パンチ / キック |

技に専用の絵を付けたいときは `move:` に技の ID を続けて書きます
（例: `"move:fireball"`, `"move:super_combo"`）。技の ID は
`data/moves/<キャラクターID>/` のファイル名と同じです。
